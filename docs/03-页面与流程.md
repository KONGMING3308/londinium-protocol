# 03 页面与流程（四人联机版）

> 本文档已按「四人线上联机」重写。另有「本地热座调试模式」，它与联机共用同一套页面，
> 只是把传输层换成内存实现，差异见文末附录。

## 一、页面清单

| 路由 | 文件 | 用途 | 关键交互 |
|---|---|---|---|
| `/` | `src/pages/HomePage.tsx` | 联机入口：填昵称、创建房间、凭 4 位房间码加入 | 填昵称 → 创建房间 / 加入房间 |
| `/lobby` | `src/pages/LobbyPage.tsx` | 大厅：展示房间码与 4 个座位，各自点准备 | 复制房间码、准备／取消准备、离开房间 |
| `/briefing` | `src/pages/BriefingPage.tsx` | 战前简报：公开情报 + 只看自己的胜利条件 | 查看我的目标 → 确认（四人全确认后开局）|
| `/round` | `src/pages/RoundPage/`（`RoundPage.tsx` + `PickingPanel` / `CouncilPanel`） | 回合操作：四人并行暗选 → 盟约窗口 | 暗选 2 张行动牌、处置中立援助与指定牌、结盟提议／回应、点就绪 |
| `/resolve` | `src/pages/ResolvePage.tsx` | 回合结算：剧情回顾、日志、数值面板、我这对同盟的阵营交换 | 选 1 张阵营交换牌或「这回合不谈」、进入下一回合 |
| `/board` | `src/pages/BoardPage.tsx` | 对局总览与完整战报（只含公开信息） | 返回回合操作 |
| `/result` | `src/pages/ResultPage.tsx` | 终局排名与胜者宣告 | 离开房间，再来一局 |
| `/rules` | `src/pages/RulesPage.tsx` | 规则手册：胜负、流程、数值、四种牌、结算顺序、同盟、KEY 标签、胜利条件、剧情、FAQ | 只读（带锚点目录） |
| `/guide` | `src/pages/GuidePage.tsx` | 新手引导 | 只读 |

## 二、跳转关系

路由由状态机驱动：服务端推进阶段后，四个客户端各自算出租 `screenOf(room)`，由 `App.tsx` 的 `PhaseSync` 自动跳转。页面内部不写「阶段不对就跳走」的守卫，避免多人多页互相打架。

```
Home(/)
  └─ 创建房间 / 加入房间 → Lobby(/lobby)

Lobby（四人各自在自己的设备上）
  └─ 四人全部准备 → 服务端 startMatch → Briefing(/briefing)

Briefing（四人各自看自己的目标）
  └─ 四人全部确认 → 服务端发牌 → Round(/round)

Round（四个阶段，四人并行）
  ├─ picking   四人同时从 3 张行动牌里选 2 张 + 处置指定牌 → 四人全部提交后 → council
  ├─ council   盟约窗口：提议 → 对方同意 才成立；四人全部点就绪 → 结算
  └─ resolved  由 Resolve(/resolve) 呈现

Resolve
  ├─ 有同盟的玩家：我这对的 2 张交换候选 → 选 1 张或「这回合不谈」（并行，不用排队）
  ├─ 四人全部点进入下一回合 → 未结束则回 Round（下一回合）
  └─ 已分胜负 或 第 7 回合打完 → Result(/result)

Result
  └─ 离开房间 → Home(/)
```

## 三、每页元素与交互

### Home 首页
- 昵称输入（最多 12 字，持久化到 localStorage）。
- 「创建房间」：成为房主，服务端生成 4 位房间码。
- 「加入房间」：输入 4 位房间码（自动转大写、过滤非字母数字）。
- 连接状态提示与可关闭的错误条（房间不存在 / 房间已满 / 对局已开始）。
- 未连接时建房与加入按钮禁用，并给「重新连接」入口。

### Lobby 大厅
- 房间码大号等宽展示 + 一键复制（方便念给朋友）。
- 4 个座位卡：名字、房主标记、在线状态、准备状态；自己那一张高亮；空位显示「等待加入…」。
- 「准备 / 取消准备」切换；「已准备 x / 4」进度。
- 「离开房间」两次点击确认；房主离开后房主身份顺延给剩下的第一位。

### Briefing 战前简报
分两段，目的是让胜利条件成为真正的秘密信息。

**第一段 · 公开情报**（全桌可见）
- 四张阵营卡：玩家名、阵营名、T1/T2/T3 强度、剧情摘要；胜利条件一栏显示「本人私下确认」，不渲染任何目标文本。
- 两组信息：本局敌对阵营数量、本局可结盟组合（由 `canAlly()` 预计算）。
- 第 1 回合剧情标题与描述。

**第二段 · 我的目标**（只有自己看得到）
- 点「查看我的目标」后展开自己的阵营卡、胜利条件与三项初始数值。
- 点确认后按钮变「已确认，等待其他玩家…（x / 4）」；四人全部确认即进入第 1 回合。
- 与原热座版不同：不再有「把设备传给下一个人」的交接流程，因为每个人本来就在自己的设备上。

### Round 回合页

**暗选阶段（四人并行）**
- 顶部显示本回合盟约事件与四人提交状态条（`room.seats[].submittedPick`）。
- 自己未提交时：
  - 3 张阵营行动牌网格（战略轴互不相同），选中高亮；必须选满 2 张。
  - 中立援助区：1 张随机中立援助，不占 3 选 2 名额；可接受或拒绝。
  - 指定牌区：上回合保留牌（若有）与本回合新发牌，五个互斥选项：
    - 有保留牌：打出保留的牌 / 保留上回合的牌 / 打出本回合新牌 / 保留本回合新牌 / 两张都不留；
    - 无保留牌：打出新牌 / 保留到下一回合 / 弃置。
  - 指定牌打出时需选择目标玩家（任意其他未出局玩家）；流亡者不能打出指定牌，只能保留。
  - `play` 与 `keep` 永远互斥；未满足条件时「确认提交」禁用。
  - 代价不足的牌标红但仍可打（透支），并给出合计代价超支警告。
- 自己已提交时：显示「已提交，等待其他玩家（x / n）」与等待名单。
- 出局者显示旁观面板，不占用「全员就绪」的分母。

**盟约阶段**
- 展示当前同盟配对与同盟对数（x / 2）。
- 发起结盟：列出可结盟对象（对方无同盟、未背刺、双方阵营历史上可合作），点击发出提议。
- 收到提议时显示「xxx 请求与你结盟」+ 同意／拒绝。**结盟必须双方同意才成立**。
- 自己已有同盟时可「撕毁盟约」（二次确认），撕毁者标记 `betrayed` 并永久失去资格。
- 「我准备好了」→ 四人（未出局者）全部就绪后服务端结算。

### Resolve 结算页
- 本回合剧情标题与描述、盟约事件。
- 若已产生胜者：金色胜利横幅（阵营名 + 判定理由）。
- 四宫格状态 + 本回合战报。
- **阵营交换（仅自己有同盟时显示）**：
  - 我这对同盟的 2 张候选牌 + 「这回合不谈」按钮。
  - 每对同盟独立并行拍板，不需要排队等别桌。
  - 已拍板后显示「本回合已拍板」；谈成时只显示「已谈成（下回合生效）」，不展开具体收益——对手看不到你的候选，也不该在结算页把条款摊开。
  - 无同盟时显示「你没有同盟」；有同盟但本回合没发到牌显示「本回合没有同盟交换」。
  - 第 7 回合起不再发放交换牌。
- 底部「进入下一回合」→ 四人全部就绪后服务端推进；已分胜负或到第 7 回合则改为「查看最终结算」。

### Board 总览
- 回合时间轴、四宫格阵营面板、完整日志（限 40 条）。**只展示公开信息**，不含任何人的手牌与胜利条件。

### Result 终局
- 胜者或无胜者标题、判定理由、以及「你就是赢家 / 这一局的胜利不属于你」。
- 按三项数值总和排序的排名列表（自己那一项高亮）。
- 最近 6 条战报摘要、「离开房间，再来一局」。

### Guide / Rules
- 内容与热座版一致，属于规则文本，不因联机改造而变化。

## 四、多人并行时的界面约束

1. **绝不展示他人私有信息**。服务端下发的 `match.players` 是脱敏的（无 `hand` / `heldDesignated` / `victory`），前端也不得用 `FACTION_MAP[...].victory` 反推别人的目标。
2. **不做乐观更新**。提交后按钮置灰、显示「等待其他玩家」，一切以服务端快照为准；提交被拒时解除锁定并提示「上一次提交没有被服务器接受」。
3. **进度分母按未出局人数算**。出局者不再参与「所有人就绪」的判定，否则会永远凑不满。
4. **等待状态要可见**。`room.seats[].submittedPick` / `.councilReady` / `.readyNext` 三个布尔量是四人进度的唯一来源。

## 五、断线与重连

- 大厅阶段断线 = 离开房间，座位释放给其他人；房主离开时房主身份自动顺延。
- 对局开始后断线 = **保留座位**，凭 localStorage 里的 token 自动重连回原座位，手牌与状态全部保留。
- 服务端下发 `seq` 单调递增，客户端只接受更大的快照，避免乱序 / 迟到快照把界面拉回旧状态。
- 服务端重启会丢失内存中的房间（客户端会重连但房间已不存在），需要重新建房。

## 附录：本地热座调试模式

历史上是本地四人热座：`/` 上是 `SetupPage`（填 4 个名字直接开局），回合页用 `HandoffPanel`
做「把设备交给下一位」的物理遮挡，状态存在浏览器 localStorage（`gameStore` + `gameApi`），
结算页阵营牌按座次逐人交接（`factionPickQueue`）。

联机改造后这套**独立规则实现**已被删除（两套规则并存必然漂移），但「一台设备调试四人局」
这个需求本身是合理的，所以以另一种方式保留了下来：

| | 旧热座版（已删除） | 现在的本地调试模式 |
|---|---|---|
| 规则来源 | `gameApi` 里独立的实现 | **与服务端同一个** `src/game/engine.ts` |
| 传输 | 直接改 store | 内存 `LocalServer`（`src/net/localServer.ts`） |
| 入口 | `/` 就是 SetupPage | 首页「本地热座调试」，或 `?local=1` |
| 页面 | 一套热座专用页面 | **复用联机的全部页面** |
| 视角切换 | `HandoffPanel` 遮挡交接 | 底部调试栏点名字切换 |

这样做的关键收益：**规则只有一份**。本地调试时看到的行为就是线上行为，
不会出现「热座能过、联机能过、线上崩」这类三套实现互相打架的问题。

页面差异只有两处：
- 顶部不显示连接状态，改显示「本地热座调试」徽标（因为确实没有连接）；
- 底部多一条调试栏（切换操作者 / 一键全员准备 / 一键全员确认）。

其他页面（大厅、简报、回合、结算、终局）与联机模式完全共用同一套组件。
