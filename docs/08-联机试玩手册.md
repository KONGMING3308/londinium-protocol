## 一、先选一条启动路径

两种模式**都能四个人玩**，区别是「怎么让别人连进来」。四个人在同一台电脑上开四个标签页测试，两条都行；**拉真朋友开黑，用路径 B**（少一个端口、少一层代理，排查问题简单）。

| | 路径 A：开发模式 | 路径 B：正式模式（推荐开黑） |
|---|---|---|
| 命令 | `npm run dev:online` | `npm run build` 然后 `npm start` |
| 端口 | 前端 5173 + 服务端 8787 | 只有 8787（页面和联机同一个端口） |
| 本机访问 | `http://localhost:5173/` | `http://localhost:8787/` |
| 局域网访问 | 支持（脚本已加 `--host`） | 支持 |
| 改代码即时生效 | 是（热更新） | 否（要重新 build） |
| 适合 | 自己调试、改样式、看代码效果 | 真的叫朋友来玩 |

### 路径 A：`npm run dev:online`

在项目根目录开一个 PowerShell 窗口：

```powershell
npm run dev:online
```

看到这几行就算成功（两边都起来，最后还会打印一个「发给朋友」的局域网地址）：

```
[server]   HTTP   http://localhost:8787/
[server]   WS     ws://localhost:8787/ws
[vite]     ➜  Local:   http://localhost:5173/
[vite]     ➜  Network: http://192.168.100.68:5173/

  ── 四个人联机 ──────────────────────────────
  本机测试：  http://localhost:5173/
  发给朋友：  http://192.168.100.68:5173/
  ────────────────────────────────────────────
```

> 「发给朋友」那一行的 IP 是脚本自动探测的本机局域网地址，直接复制给朋友即可。
> 如果没打印这一段，说明没探测到局域网网卡（比如只连了虚拟网卡），
> 手动用下面第二节的方法查 IP 也一样。

### 路径 B：`npm run build` + `npm start`（开黑推荐）

```powershell
npm run build
npm start
```

看到这一行就算成功：

```
  伦蒂尼姆协议 · 联机服务端
  HTTP   http://localhost:8787/
  WS     ws://localhost:8787/ws
  静态   D:\TRAE的屎\dist
```

这个进程同时提供网页和联机服务，**只有一个端口 8787**，局域网配置最简单。四个人打开 `http://<开服那台机器的IP>:8787/`。

## 二、局域网：让别人的电脑连进来

主机和朋友的电脑要连**同一个路由器/同一个 Wi-Fi**（同一个局域网）。

### 1. 查自己的内网 IP

```powershell
Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object { $_.IPAddress -notlike '127.*' -and $_.IPAddress -notlike '169.254.*' } |
  Select-Object IPAddress, InterfaceAlias
```

输出里 `InterfaceAlias` 是 `WLAN`（无线）或 `以太网`（网线）的那一行，`IPAddress` 就是你要的，例如 `192.168.100.68`。

> 这个 IP 可能会变（路由器重新分配）。开黑前现查一次最稳。

### 2. 确认监听了所有网卡（两条路径都不用改）

两条路径**默认都已经监听所有网卡**，正常情况下这一步什么都不用做：

- **路径 B**：`npm start` 默认 `HOST=0.0.0.0`。
- **路径 A**：`dev-online.mjs` 已经给 vite 带了 `--host`，服务端 8787 本来是 `0.0.0.0`。

判断依据很简单：路径 A 的启动日志里如果有 `Network: http://192.168.x.x:5173/` 这一行（而不是 `Network: use --host to expose`），就说明已经对外开放了。

只有一种例外：如果你是不用脚本、自己单独跑 `npx vite`，那它默认只监听本机，需要手动加参数：

```powershell
npx vite --host
```

### 3. 放行防火墙

Windows 默认会拦掉外部进来的端口。**要用管理员身份打开 PowerShell**（开始菜单搜 PowerShell → 右键「以管理员身份运行」），再执行：

```powershell
# 路径 B（只用 8787 一个端口）
New-NetFirewallRule -DisplayName "伦蒂尼姆协议 8787" -Direction Inbound -Protocol TCP -LocalPort 8787 -Action Allow

# 路径 A 还要额外放行 5173
New-NetFirewallRule -DisplayName "伦蒂尼姆协议 5173" -Direction Inbound -Protocol TCP -LocalPort 5173 -Action Allow
```

不想敲命令的话，用鼠标：`控制面板 → 系统和安全 → Windows Defender 防火墙 → 高级设置 → 入站规则 → 新建规则 → 端口 → TCP → 特定本地端口` 填 `8787` → 允许连接。

> 玩完想撤销，用 `Remove-NetFirewallRule -DisplayName "伦蒂尼姆协议 8787"`。

### 4. 朋友该访问的地址

| 你的路径 | 朋友打开 |
|---|---|
| 路径 A | `http://192.168.100.68:5173/`（换成你的 IP） |
| 路径 B | `http://192.168.100.68:8787/`（换成你的 IP） |

`npm run dev:online` 启动完会自动打印「发给朋友」那一行，直接复制即可。

**先自己在本机试一下 `http://localhost:端口/` 能打开，再叫朋友。** 自己都打不开，别人肯定也不行。

## 三、开一局：真人视角的完整步骤

四个人**各自一台设备、各自一个浏览器**（同一台电脑开四个标签页也能测，但要开无痕/不同浏览器，否则会共用登录身份）。

1. **各自打开网址、填昵称**
   第一件事是填「你的昵称」（最多 12 字，大厅里其他三人都看得到）。填完按钮才会亮。

2. **一个人点「创建房间」**
   谁都可以当房主，房主只是「第一个进房间的人」，中途离开也不会解散房间。点完跳进大厅，屏幕中间有个**大号 4 位房间码**，例如 `7KQ2`，旁边有「复制房间码」。

3. **把房间码告诉另外三个人**
   微信发、语音念都行。**不用管大小写**，输入框会自动转大写，小写也能进。

4. **另外三人输码入房**
   在首页「加入房间」框输入这 4 位码 → 点「加入房间」。

5. **大厅里确认人都齐了**
   四个人看到同样的 4 个座位卡（名字、房主标记、在线状态），空位显示「等待加入…」。自己那一张有**琥珀色高亮边框**和「（你）」标记。此时所有人都是「未准备」。

6. **每个人点「准备」→ 四人齐自动开局**
   准备状态其他人立刻看得到，顶部显示「已准备 x / 4」。**必须 4 个人全部准备才会开局**——三个人准备好、第四个人没点，是**不会**开始的；房间不满 4 人也不会开始。第四人点完的瞬间，四台屏幕**同时**跳到战前简报。

## 四、联机版和以前的「热座版」有什么不一样

> 这段是给**玩过旧版的老朋友**看的。按老习惯操作会踩坑。

| | 旧版（热座，一台设备传着玩） | 现在（联机，各看各屏） |
|---|---|---|
| **暗选** | 选完把设备递给下一个人 | **四个人同时各选各的**，不用等谁，也不用传设备 |
| **战前简报** | 设备依次传阅，用手遮屏幕 | **各看各屏**。别人的胜利条件物理上不在你浏览器里，看不到也不需要遮 |
| **结盟** | 同一台设备上自己点两下就成立 | **必须提议 → 对方点同意**。单方面点不出盟约 |
| **阵营交换** | 按座次逐对排队，等人拍板 | **每对同盟并行拍板**，不用排队等别人 |
| **等待** | 一直是同一个人在操作 | 你选完就等着，页面会显示「已提交，等待其他玩家（x/4）」 |

> **只是想一个人试试？** 首页最下面有个「本地热座调试」，进去还是能一台设备跑完四个座位
> （页面底部可以切换当前操作者），规则和联机完全一样。但它不联网，只适合自己摸流程。

### 几个容易搞错的地方

- **「准备」不是「开始游戏」**。它只是告诉房间「我人到了」。要 4 个人都点。
- **暗选提交后不能改**。选之前想清楚，提交后只能等别人。
- **结盟是双向的**。你发出申请后，对手那边会弹出「xxx 请求与你结盟」，他点同意才成立。点了拒绝或者不理你，就没成。
- **撕毁盟约代价很重**：会**永久**失去结盟资格，本回合起同盟加成全部失效，只有背刺加成照常结算。想清楚再点。
- **胜利条件只有自己知道**。就算朋友坐在你旁边，他屏幕上也不会出现你的目标。

## 五、断线了怎么办

先分清：**「断线」和「离开房间」不是一回事。**

**大厅阶段有人关页面 / 断网** → 座位**立刻释放**（别人看到「等待加入…」），剩下的人**不会**开局。让他重新打开网址、重新输房间码即可（大厅阶段没有自动回座）。

**对局中有人断线 / 关页面 / 手机切屏** → 座位**保留**，不踢人，别人也看不到「掉线」标记。让他在**同一浏览器**重新打开地址、或直接把页面切回来就行——会**凭本地身份自动回到原座位**，不用重输房间码，手牌和进度都还在。前提是没清过浏览器数据，清了就回不去。

> 座位与重连凭证保留 **24 小时**（v0.4.5）。**大厅阶段断线也不会丢座位了**；
> 而且四个人**一起**切屏时倒计时会**冻结**——不会被托管把你没打的牌代打掉，回来接着算。

**只有一台电脑，想两个人对打** → 开两个标签页就行：**A 页建房，B 页用房间码加入**。每个标签页是一条独立会话，刷新只恢复自己那一局，不会互相顶号（v0.4.6 之前会互踢，那是 bug，已修）。注意**一个标签页只能坐一个座位**，别在两个页面里同时操作同一个玩家。

**对局中网络卡了一下** → 顶部显示「重连中…」和底部黄色提示条。**什么都别做，等它自己重连**，一般几秒恢复，座位不丢。切回前台或网络恢复时会立刻重连，不用手动刷新。

**开服那台电脑重启了服务（`npm start` 重开）** → **对局不会丢**（v0.4.7 起房间落盘到 `data/rooms.json`）。服务端启动时会把进行中的对局读回来，玩家刷新页面就凭 token 回到原座位，回合和手牌都在——前提是**重新连上原来那个端口**。

> 唯一的损失是**最后一秒内的动作**：写盘是攒 800ms 一次，断电（SIGKILL）最多丢最近一秒的进度；正常 Ctrl+C / 停止服务（SIGINT/SIGTERM）会先把房间写完再退出，一点不丢。

## 六、常见故障排查

### 页面能打开，但一直显示「正在连接服务器」/「未连接」

| | |
|---|---|
| **现象** | 首页能加载出来，但「创建房间」「加入房间」按钮是灰的，顶部一直转圈 |
| **原因** | 前端起来了，但服务端没起来（路径 A 只开了 vite 没开 server），或者服务端崩了 |
| **解决** | 看开服那个终端窗口，`[server]` 那段有没有正常输出。崩了就 `Ctrl+C` 停掉，重新 `npm run dev:online` 或 `npm start`。确认 `http://localhost:8787/healthz` 返回 `{"ok":true,...}` |

### 输入房间码提示「房间不存在或已解散。」

| | |
|---|---|
| **现象** | 红色错误条，「房间不存在或已解散。」 |
| **原因** | ① 码输错了（4 位，容易看错 `B/8`、`0/O`）② 房主那边房间已解散 ③ 服务端重启过，房间没了 |
| **解决** | 跟房主核对一遍房间码。房主那边如果大厅还在，让房主把码**复制**发过来，别手打 |

### 第四个人进不来（房间已满 / 对局已开始）

| | |
|---|---|
| **现象** | 提示「房间已满（4/4）」或「对局已开始，无法中途加入」 |
| **原因** | 房间固定 4 人。已经 4 人时第 5 个进不来；**开局后任何人都不能中途加入** |
| **解决** | 满员：让多出来的那个人等下一局。已开局：这局没法加人，要么等他打完，要么四个人重开一局 |

### 局域网里朋友访问不了（转圈/打不开）

按顺序查这四步，基本能定位：

1. **是不是同一个 Wi-Fi？** 有人连了手机热点或访客网络，就不在同一网段。
2. **IP 对不对？** 开服机器上重新跑一遍查 IP 的命令，确认没变。
3. **前端有没有监听所有网卡？** 看启动日志里有没有 `Network: http://192.168.x.x:5173/` 这一行。如果显示的是 `Network: use --host to expose`，说明没用 `npm run dev:online` 而是自己单独跑了 `npx vite`，加 `--host` 重启。
4. **防火墙放行了吗？** 用管理员 PowerShell 加的规则才生效。临时验证：先把 Windows 防火墙整体关掉试试能不能连，能连说明就是防火墙问题，再回去加规则。

> 两条路径在验证中都是**局域网直接可用的**，不用改任何代码。局域网连不上，优先怀疑上面这几条，别怀疑程序。

### 有人中途退出，卡住不推进

| | |
|---|---|
| **现象** | 自己已经提交/就绪了，但一直显示「等待其他玩家（x/4）」，永远等不到 4/4 |
| **原因** | 有人掉线后**座位保留但不提交**。这游戏**没有超时踢人、也没有 AI 托管**，必须等他回来 |
| **解决** | 让掉线的人按「情况 2」重开浏览器回座。如果他确定不玩了，**这局没法继续，只能四个人重开**（对局开始后谁都不能离座，也没有投降/重开按钮） |

> 这是当前版本最大的体验缺陷，不是 bug。开黑前先说好「中途别跑」。

## 七、实测环境说明

**真跑过、验证通过的：**

- Windows + Node.js **20.18.0** + Microsoft Edge（Chromium 内核）
- 四个独立浏览器上下文模拟四台设备，**完整走通**：建房 → 三人入房 → 四人准备 → 自动开局 → 各自确认简报 → 暗选/盟约/结算 → 打到第 7 回合终局
- **路径 B 单端口模式**，分别从 `127.0.0.1:8787` 和**局域网 IP** `192.168.x.x:8787` 访问，都能正常开局
- 大厅阶段刷新 → 回原大厅、房间码不变；对局中刷新 → 自动回原座位
- 大厅阶段有人关页面 → 座位释放；对局中有人关页面 → 座位保留，用原浏览器重开**自动回原座位**
- 服务端重启 → 页面停在旧对局显示旧数据；刷新后回首页提示「房间不存在或已解散。」

**没验证过、可能有问题：**

- **Safari / Firefox**：只在 Edge 上实测过，代码用标准 Web API、理论上可用，但**没实测**。
- **手机浏览器**：响应式布局窄屏无横向溢出，但游戏信息量大，**没针对手机优化过**，不推荐。
- **公网联机**（不在同一局域网）：需要端口映射或内网穿透，**本文未覆盖也没验证**。
- **防火墙规则命令**：按微软官方文档写的，但**没有管理员权限实跑过**。命令报错就用鼠标操作那条路径。

**自己跑测试确认：**

```powershell
npm test                        # 十四个套件共 390 项：引擎压测 + 协议级联机 + 安全边界 + 平衡门槛锁定 + 断线恢复 + 多标签页等
npm run test:browser            # 四个真实浏览器窗口跑完整局（需先 npm run build）
```
