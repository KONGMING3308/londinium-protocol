## 一、项目概述与设计目标

### 1.1 背景

《明日方舟》第 9–14 章（伦蒂尼姆篇）包含萨卡兹军事委员会、典范军、罗德岛、塔拉／深池、整合运动、市民自救军等多方势力。原作以线性叙事呈现多方博弈，缺少一套可上手、可反复验证的对抗化抽象。

本项目将该战役抽象为一款**四人线上联机回合制卡牌策略游戏**：每名玩家随机获得一个阵营，用人力／补给／士气三项数值与卡牌对抗，在 7 个回合内抢先达成各自的非对称胜利目标。四人各自用一台设备凭房间码进入同一大厅，点准备后由服务端自动开局，全程服务端权威结算、客户端只提交「意图」。

### 1.2 目标用户

| 角色 | 说明 | 使用场景 |
|---|---|---|
| 产品设计者（用户本人） | 非技术人员，负责规则设计与平衡 | 本机起服务端，验证机制是否成立 |
| 3 名同玩好友 | 熟悉《明日方舟》剧情 | 各自设备凭房间码进同一房间，联机对局 |
| 部署者 | 拥有服务器的用户 | 打包上传后 `node server.mjs` 直接部署 |

### 1.3 痛点

1. 原作势力关系复杂，难以直观判断「谁会赢、为什么赢」。
2. 想验证对抗机制，但缺少可运行的载体，只能靠纸面推演。
3. 数值与卡牌的平衡需要反复试玩，缺少快速改数据、即时生效的工具。

### 1.4 用户故事

| 编号 | 用户故事（As a… I want… So that…） | 对应功能 |
|---|---|---|
| US-01 | 作为组织者，我希望输入 4 名玩家后一键开局，阵营随机且互不相同 | F-01 |
| US-02 | 作为玩家，我希望开局时看到自己阵营的胜利条件与全桌敌对关系 | F-02 |

### 1.5 非目标

- 不做账号体系、好友系统、排行榜、云存档。
- 不做 AI 对手（离线托管 `autoActFor` 只作「超时兜底」，不是可对战的 AI）。
- 不做美术资源、地图、动画演出。
- 不做跨设备进度同步（进度在服务端内存里，随房间 TTL 过期）。
- 不做生产级数值平衡，平衡性以实测反馈迭代。

### 1.6 验收口径

只验证一件事即可证明游戏可用：**4 名玩家各自一台设备凭房间码进入同一房间，从准备、开局一路操作到第 7 回合结算，期间针对、同盟、流亡、判胜四类机制各至少触发一次，无报错、无卡死、无越权（看不到别人的手牌与出价）。**

（具体的 Given／When／Then 见 [第八章](#八验收标准)。）

### 1.7 设计目标与约束

| 目标 | 落地要求 | 代码落点 |
|---|---|---|
| 选择「走哪条路」而不是「哪个数字大」 | 同一手 3 张行动牌的战略轴互不重复，发牌按轴分桶 | `src/utils/game/deck.ts` `pickByAxis` |
| 每张牌都有取舍 | 行动牌必须带代价（加 A 减 B），但不得用「仅在同盟时生效」或「概率成功」做取舍；行动牌一律确定生效 | `src/mocks/cards/*.ts` |
| 阵营差异来自非对称目标而非数值碾压 | 胜利条件写在 `FactionDef.victory`，六阵营各不相同 | `src/mocks/factions.ts` |
| 社交张力可被观测 | 同盟资格按剧情锁定；撕约即刻生效且永久损失资格 | `src/mocks/factions.ts`、`src/utils/game/alliance.ts` |
| 能快速改数据 | 数值、卡牌、剧情修正、盟约事件、中立资源点全部集中在 `src/mocks/` | `src/mocks/` |
| 联机不窥屏 | 服务端权威，按视角脱敏下发：手牌／保留牌／胜利条件／同盟交换候选／出价只发给有权者 | `src/shared/protocol.ts`、`src/game/engine.ts` `viewFor` |
| 掉线不丢人 | 断线重连凭 token 回原座位，心跳 + 指数退避 | `src/net/client.ts` |
| 超时不卡局 | 每阶段服务端计时，超时托管兜底推进 | `src/game/engine.ts`、`server/index.ts` |
| 可复盘 | 每回合结算日志、完整战报、终局排名 | `src/components/LogList.tsx`、`ResolvePage`、`ResultPage` |

### 2.2 已锁定边界

1. 技术栈按 `AGENT.md`：React 18 + TypeScript(strict) + Vite 5 + React Router v6 + Tailwind + lucide-react；状态用 Zustand 4；后端 Node 20 + `ws`，经 esbuild 打成单文件 `server/dist/index.mjs`。
2. 游戏为**四人线上联机**：一人建房拿房间码，三人凭码进房，四人全部点准备后服务端自动开局；同一引擎另接「本地热座调试模式」供单人调试。
3. 服务端权威：所有随机、发牌、结算、判胜都在服务端执行，客户端只提交意图；快照按视角脱敏，手牌／保留牌／胜利条件／出价只发给有权者。
4. 每局从 6 个阵营中随机抽取 4 个，四人阵营互不相同，且至少存在一对敌对关系（`assignFactions()` 重抽至满足，失败兜底 `SARK/VIC/RI/TARA`）。
5. 数值维度：人力 M、补给 S、士气 R；上限 50，溢出直接截断。
6. 每回合每人 5 张手牌：3 张阵营行动牌（战略轴互不重复，3 选 2）＋ 1 张中立援助（不占 3 选 2 名额，默认接受打出、可主动拒绝弃置，成功率 0.45–0.70，失败仅 -1 补给或 -1 士气）＋ 1 张指定牌（按回合发放，可指向任意玩家，可保留 1 张或弃置）。
7. 指定牌可打出或保留一回合，保留上限 1 张；保留则本回合不结算。
8. 胜负在 R6、R7 回合结束时统一判定，先达成者胜；R1–R5 不判胜。
9. 崩溃（任一数值 ≤0）可触发一次流亡：三项重置为 5/5/5，上限压制到 12，KEY 牌效果减半，不能主动针对他人。
10. 同盟上限 2 对，每名玩家同时只能属于 1 个同盟；仅剧情中实际结盟的势力可结盟（SARK–TARA、VIC–RI、VIC–SSC、RI–REU、RI–SSC、REU–SSC），⚔ 敌对势力不可结盟。
11. 阵营牌为按同盟组合分池的双向「交换牌」（6 组合 × 6 张 = 36 张）；每一对同盟在结算页共享 2 张候选、协商谈成 1 张或放弃，条款对双方同时结算，效果在下一回合开始前生效（先于回合修正与盟约事件）；第 7 回合结束后不再提供。发放时排除已出局与流亡玩家。
12. 撕毁盟约须在针对牌结算前宣告，宣告当回合立即生效。
13. 每回合刷 2 个中立资源点，四人秘密出价、最高价独得（并列流拍、出价照扣），出价从补给里扣。
14. 剧情每回合从 3 个候选里随机抽 1 个（不是固定剧本）；盟约事件无盟约不触发、有盟约 50% 触发、触发后三类走向随机选一。
15. 每阶段服务端计时：暗选 30s／盟约 45s／结算 60s；超时由 `autoActFor` 托管兜底（保守原则：不替玩家花补给出价、不替玩家打指定牌）。
16. 结算顺序：阵营牌（下回合开始前）→ 回合修正 → 调停保护（只保护打出者与盟友）→ 行动牌代价 → 指定牌目标／防御 → 击穿／落空 → 指定牌命中或反噬 → 行动牌效果（含成功率判定）→ 盟约事件 → 同盟互援 → 上限／流亡。

### 3.2 回合流程

7 回合制，四人**并行暗选**（不再是热座轮流传设备）。服务端权威：所有随机、发牌、结算、判胜都在服务端执行，客户端只提交「意图」，收到全量快照后更新界面。

**一局的完整生命周期**（`RoomPhase`）：

| 阶段 `phase` | 界面 | 内容 | 出口 | 时限 |
|---|---|---|---|---|
| `lobby` | 大厅 | 房主显示房间码，四人各自点准备；随时可取消／离开 | 四人全部准备 → 服务端自动开局 | 不计时 |
| `briefing` | 战前简报 | 展示自己阵营、目标、敌我与可结盟组合、R1 剧情 | 各自点「我已了解」 | 60s |
| `picking` | 暗选面板 | 看 5 张手牌 → 选 2 张行动牌 → 处置中立援助 → 处置指定牌并选目标 → 对中立资源点出价 | 提交后等待；四人都提交（或超时托管）进入 `council` | 30s |
| `council` | 盟约窗口 | 公开结盟／撕约 | 各自点就绪；全就绪（或超时）进入结算 | 45s |
| `resolved` | 结算页 | 战报、四宫格状态、胜负横幅、同盟交换 2 选 1（按对协商）、竞标结果复盘 | 进入下一回合或终局 | 60s |
| `result` | 终局页 | 胜者宣告与排名 | 再来一局 | 不计时 |

**每阶段超时托管**（`server/index.ts` `onPhaseTimeout` → `autoActFor`）：到点后把「还没动作」的玩家逐个托管掉，直到阶段推进或没有可托管对象。托管遵循**保守原则**：不替玩家花补给出价、不替玩家打指定牌，只做「能安全推进」的最低限度动作（如默认选 2 张行动牌、拒绝中立援助、盟约窗口直接跳过）。

回合启动（`beginRound`）的固定顺序：

1. 应用上一回合选定的**阵营牌**（`factionPending`），并把它们移入阵营牌弃牌堆；
2. 应用本回合**剧情修正**（每回合从 3 个候选里随机抽 1 个，`storyCandidates(round)`），并清 `betrayedThisRound`；
3. 盟约事件**不在此处**判定——见第 4 步与 [3.8](#38-盟约事件)；
4. 刷 2 个中立资源点（`drawNeutralPoints`），随后全员发牌，进入并行 `picking`。

回合收尾（`nextRound`）：若有胜者或当前已是 R7 → `result`；否则回合 +1、回到 `picking`（无热座交接页），未选择的阵营牌候选回收进弃牌堆。

**并行暗选**：四人在 `picking` 阶段**同时**提交，互不可见。服务端只下发「已提交人数」和「已出价人数」，不透露具体手牌与出价金额；直到结算后才公开全部出价（`bidResults`）。脱敏由 `viewFor()` 按「当前玩家视角」生成快照完成。

### 3.2.1 中立资源竞标

每回合 `beginRound` 从 10 张中立资源点里洗牌后刷 **2 个**（`drawNeutralPoints`，用回合号做偏移避免固定开局），四人**秘密出价**争夺：

- 出价从**补给**里扣，输了也不退；最高价独得该点奖励，其余人的出价全部打水漂。
- 最高价**并列则流拍**，谁都不拿、出价照扣。
- 出价低于 `minBid` 视为未出价；出价 0 等同于不参与（不写入出价表，也不计入「已出价人数」）；出局玩家的出价被忽略。
- **低补给保护（B7）**：结算时若该玩家扣费前补给 <5，其竞标扣费减半（向下取整，至少 1）。避免「抢点 + 被夺补给」在早期直接把薄底阵营压崩溃。
- 脱敏：暗选阶段只暴露「已有 N 人出价」与「我对某点的出价」，不透露别人出的金额；结算后 `bidResults` 公开全部出价供复盘。
- 奖励幅度受约束：不高于行动牌正向收益（否则抢点成为唯一最优解），`minBid` 有实感（避免「出 1 点碰运气」变成无成本摸奖）。

资源点 10 张（`src/mocks/neutral.ts`）：`N-01` 疤痕商场的军械（补给+4）／`N-02` 生命脊椎补给线（补给+2 人力+2）／`N-03` 城头广播站（士气+4）／`N-04` 黑钢雇佣合同（人力+4）／`N-05` 废品回收站（补给+3）／`N-06` 教堂救济点（士气+2 人力+1）／`N-07` 诺伯特区制高点（士气+2 补给+1）／`N-08` 巫妖藏书（士气+3 补给+1）／`N-09` 拉特兰调停席（士气+2）／`N-10` 走私商队（补给+2 士气+1）。

### 3.3 手牌结构

每回合每名玩家固定 5 张：

| 牌位 | 张数 | 来源 | 是否占「3 选 2」名额 | 可保留 | 结算方式 |
|---|---|---|---|---|---|
| 阵营行动牌 | 3 | 本阵营行动池，按轴分桶抽取，轴互不重复 | 是（3 选 2） | 否，未选即弃 | 支付代价 → 结算效果 |
| 中立援助 | 1 | 中立公共池随机 1 张 | **否** | 否，可接受或拒绝 | 预掷成功率 → 成功取原效果，失败取轻度负面 |
| 指定牌 | 1 | 本阵营指定牌表中 `round` 等于当前回合的那 1 张（静态卡，不进牌堆） | 否 | 可保留 1 回合 | 宣告 → 防御 → 命中／落空 |

提交条件：**必须选满 2 张行动牌**，且指定牌决策（打出／保留／弃置）完整；选择「打出」时必须选定合法目标，否则「确认并提交」保持禁用。中立资源出价可选（不出价 = 不参与本回合争夺）。

弃牌路由（`submitPick` / `resolve`）：中立援助回到中立弃牌堆，阵营行动牌回到本人弃牌堆，指定牌不进入任何牌堆（静态卡）。

### 3.4 阵营行动牌

每张行动牌带一个**战略轴** `axis`，六轴定义如下：

| axis | 名称 | 设计取向 |
|---|---|---|
| `assault` | 强攻 | 高人力增量，但扣补给或士气 |
| `logistics` | 补给线 | 补给／转换，短期弱、续航强 |
| `propaganda` | 宣传 | 士气与合法性，通常无即时战力 |
| `convert` | 转化 | 用一种资源换另一种，净收益为正但结构失衡 |
| `intel` | 情报 | 看牌／改目标／使对方免疫失效，不直接加数值 |
| `gamble` | 冒险 | 高方差：命中大赚、失败反噬 |

发牌规则（`drawActionHand`）：

1. 从本阵营行动池按 `axis` 分桶，抽 3 张轴互不重复的牌；牌堆不足时先把弃牌堆洗回再找，轴已用尽才允许重复。
2. 从中立公共池另抽 1 张中立援助，单独记录，不占 3 选 2 名额。
3. 指定牌按 `round` 固定发放，不参与抽取。

代价与前条件：

- `cost` 在结算最前面扣除（先于指定牌与效果），**即使该牌随后被针对或前置条件失效，代价也不返还**。
- `requiresAlly: true` 的行动牌在效果结算时校验：若当时没有盟友则「效果落空」（代价已付）。当前数据中只有中立池的 `G-12` 配置了该字段；阵营行动牌一律没有前置条件（此前列在这里的 S-A4／V-A3／R-A4／T-A3／E-A4／C-A4 从未落地，属设计残留）。
- 冒险轴（`gamble`）与非 gamble 牌也可能带 `roll`，统一按「预掷 → 成功取 `win`／失败取 `lose`」处理。

**防御 special（B9）**：`immunity`／`cancelCounter`／`redirect` 会让「本回合针对自己的指定牌落空」（见 [3.6](#36-指定牌)）。此前只有中立援助带这些 special（且有 `roll`，抽到才有），导致 SSC／REU 这类薄底阵营缺少稳定的防御手段。现补充两张阵营行动牌：

| 阵营 | 卡牌 | 轴 | special |
|---|---|---|---|
| SSC | `C-A11` 街角守望 | `intel` | `immunity`（免疫针对） |
| REU | `E-A10` 感染者互助 | `gamble` | `cancelCounter`（反制针对） |

### 3.5 中立援助

- 类别上仍是 `category: 'action'`、`owner: 'GENERIC'` 的行动牌，但**单独发放、单独展示、不占 3 选 2 名额**。
- 每回合随机分配 1 张；界面提供「接受中立援助（本回合打出）」与「拒绝中立援助（直接弃置）」两个选项，默认接受。
- 全部 12 张都带 `roll`：锁定区间为 0.3–0.8，当前数据实际取 0.45–0.70；成功取 `win`（含 `special`），失败只取 `lose`（-1 补给或 -1 士气）。
- 中立池 12 张、六轴各 2 张，全阵营共用；耗尽后用中立弃牌堆洗回。
- 结盟向的两张：`G-11` 中立斡旋（`coop`，有盟友时额外 +1 士气）、`G-12` 中立义勇军（`requiresAlly`，无同盟时整张牌无效）。
- 完整牌表见 [4.8](#48-中立援助g-01g-12)。

### 3.5.1 剧情事件（每回合三选一）

剧情不再是一张固定的七回合剧本表，而是**每回合从 3 个候选里随机抽 1 个**（`src/mocks/story.ts` 的 `STORY_EVENTS`，7 回合 × 3 候选 = 21 条）。同一回合在不同局里可能发生不同的事，玩家不能靠背板过关。

设计约束（写新事件时必须遵守）：① 对全场 6 阵营都生效；② 有净代价（不允许全员纯赚）；③ 单项幅度 ±1~2、总和接近 0；④ 叙事与数值一致。

剧情事件在 `beginRound` 应用（`applyStoryEvent`），并写入 `storyHistory` 供时间轴回看；完整候选表见 [附录 A](#附录-a七回合剧情候选表)。

### 3.6 指定牌

指定牌不是「给自己加数值」，而是**对一位玩家发起的行动**，打出时必须指定目标。

- 目标：任意未出局的玩家，**包括盟友，不包括自己**；目标数量不足以构成敌对关系时仍可正常打出（代码层面统一按 `targetRule: 'any'` 处理，字段中残留的 `'hostile'` 不生效）。
- 保留：可保留到下一回合（上限 1 张），保留则本回合不结算；也可直接弃置。
- 三段式：宣告 → 对方防御 → 命中／落空。防御来源为目标本回合打出的 `immunity` / `cancelCounter` / `redirect` 牌（且该牌 `roll` 成功），或拉特兰调停（`truce`）庇护。
- 命中：按 `op` 结算基础效果，并附加牌面 `effects`（部分牌同时推进战争进度）。
- 落空：按牌面 `backlash` 反噬，并写入战报。

`op` 基础效果（以 `src/utils/format.ts` 的 `OP_HIT` 与 `resolve.ts` 实现为准）：

| op | 名称 | 命中效果 | 备注 |
|---|---|---|---|
| `strike` | 打击 | 目标士气 -4，自身士气 +1 | 与牌面 `effects` 叠加 |
| `raid` | 掠夺 | 夺取目标 `min(3, 目标当前补给)` 点补给 | 目标补给不足时按实际值夺取 |
| `siege` | 围困 | 目标补给 -3 | 带 `progress` 的牌同时推进战争进度 |
| `sabotage` | 破坏 | 目标本回合的指定牌失效；自身士气 +1 | 若该牌带 `counterTag` 并击穿成功，士气奖励已在击穿时发放，不重复加 |
| `cut` | 切断 | 目标本回合**补给的正向收益归零**（已付出的代价照扣），并顺走 1 点库存 | 只抹补给，人力／士气的收益不受影响；被瓦解或落空时不产生切断 |
| `incite` | 策反 | 解除目标与其盟友的同盟（双向），自身士气 +1 | 目标本无同盟时仍 +1 士气 |
| `expose` | 揭穿 | 公开目标本回合打出的行动牌名，自身补给 +1 | 仅信息收益 |
| `decisive` | 对决 | 双方人力差 ≥3：夺取目标 `min(5, 补给)` 点补给且目标士气 -3；否则视为落空 | 差值不足时反噬按 `backlash`（默认士气 -3） |

**针对与击穿**（`counterTag` 机制）：

- 指定牌带 `counterTag` 时，检查目标**本回合打出的牌**（行动牌 + 指定牌）中是否有 `tag` 相同的 KEY 牌。
- 命中：该 KEY 牌整张收益归零，目标的 `nullifiedTags` 记入该标签，攻击者士气 +2（双方为宿敌时）／+1（否则）。
- 未命中：攻击者补给 +1，本张指定牌不再结算 `op` 收益（战报标注「落空」）。
- 推论：KEY 标签只有在**对应 KEY 牌同回合被该目标打出**时才可能被击穿。例如【国剑】只存在于 V-D3（R3 发放），因此只有在 R3 由典范军打出 V-D3、且同时被带 `counterTag: '国剑'` 的牌（T-D3 焚烧王旗）命中时，才会写入 `nullifiedTags`。

**防御与调停**：`immunity` / `cancelCounter` / `redirect` / `truce` 均需该牌 `roll` 成功才拥有对应能力（无 `roll` 视为成功）。调停只庇护**打出者本人与其盟友**，其余玩家的针对照常结算。

完整牌表见 [4.2](#42-萨卡兹军事委员会sark)–[4.7](#47-市民自救军ssc)。

### 3.7 阵营牌与同盟交换

阵营牌（`category: 'faction'`、`owner: 'GENERIC'`）是**独立于手牌的第三方系统**。自本版起改为
**按同盟组合分池**：6 种可结盟组合各有一池 6 张专属交换牌，共 36 张，只在这一对之间流通，
不进入任何玩家手牌。

核心设定：**一张牌写死两边**。每张牌声明 `pair: [甲, 乙]`，`effects` 结算给甲方，
`allyEffects` 结算给乙方；可选 `progress` / `allyProgress` 推进对应一方的战争进度。
因此「谁去点那张牌」不影响结果 —— 交换条款是固定的、可谈判的、也是公开的。

资格（同时满足）：

1. 本回合结算**未产生胜者**；
2. 当前回合 ≤ 6（第 7 回合结算后不再提供）；
3. 这对同盟的双方都未出局、未流亡；
4. 双方仍然互为盟友（`allyId` 双向互指）。

流程：

1. 结算页为**每一对合格同盟**（而非每位玩家）从该组合的专属池抽 **2 张候选**；
   本组合池不足 2 张时只洗回本组合的弃牌，不会串到别桌。
2. 两人协商后由其中一人拍板：选 1 张成交，或「这回合不谈」。
3. 选择写入 `factionPending`，键为 `pairKey`（`factionId` 排序后用 `+` 连接，如 `SARK+TARA`）。
4. 下一回合 `beginRound` **最先**生效 —— 早于回合修正，也早于盟约事件；生效后移入阵营牌弃牌堆。

结算规则：

- 生效时校验双方仍然互为盟友；若交换生效前同盟已破裂，这笔交易**作废**并写战报。
- 甲方结算 `effects`，乙方结算 `allyEffects`（正数=获得，负数=付出），双方同时承受条款。
- `progress` 记在甲方头上，`allyProgress` 记在乙方头上，用于表达「你替我干活」这类不对称交易。
- 未选中的候选与放弃只在 `nextRound` 时回收。

设计意图：同盟不再是「双方白拿增益」，而是一套**持续的价格谈判** —— 每一笔交换都可能顺带喂饱
对手的胜利条件（例如萨卡兹用物资换深池替自己推进战争进度，深池只拿到物资）。

完整牌表见 [4.9](#49-阵营牌36-张)。

### 3.8 盟约事件

盟约事件是**独立系统**：不进入手牌、不参与回合内选择，在**结算阶段**判定，结算的最后阶段对所有玩家生效。

- **触发判定**：场上没有任何盟约 → 本回合不触发；有盟约 → 50% 概率触发。
- **三类走向**（触发后从三类里等概率选一类，再从该类随机抽 1 张）：
  - `ally-boon`：对已缔结同盟的阵营有利，对孤立阵营有害；
  - `solo-boon`：对孤立阵营有利，对已缔结同盟的阵营有害；
  - `internal`：同盟成员之间互相有利有弊，孤立者不受牵连。
- 每类 2 张、共 6 张；效果分为 `allianceEffects`（同盟双方各得）与 `soloEffects`（无同盟者得）。
- 与手牌、指定牌、阵营牌互不干扰；同一张事件可在同一局重复出现。
- 完整牌表见 [4.10](#410-盟约事件p-01p-06)。

### 3.9 同盟与背刺

**结盟资格**（双向，任一不满足即不可结盟）：

| 检查项 | 规则 | 代码 |
|---|---|---|
| 剧情关系 | 仅 `ALLIANCE_PAIRS` 中的 6 组可结盟 | `canAlly()` |
| 敌对关系 | `HOSTILE_PAIRS` 中的组合永久不可结盟 | `canAlly()` |
| 个人状态 | 双方均无现有盟友、均未撕毁过盟约（`betrayed === false`） | `createAlliance()` |
| 同盟总量 | 全桌同盟对数 < 2（即最多 2 对） | `createAlliance()` |

可结盟组合：萨卡兹军事委员会–塔拉／深池、典范军–罗德岛、典范军–市民自救军、罗德岛–整合运动、罗德岛–市民自救军、整合运动–市民自救军。
敌对组合：萨卡兹军事委员会–典范军、萨卡兹军事委员会–罗德岛、典范军–塔拉／深池、典范军–整合运动、罗德岛–塔拉／深池、塔拉／深池–整合运动。

**背刺（撕约）**：

- 在 `council` 盟约窗口公开宣告，立即生效：双方 `allyId` 清空，撕约方 `betrayed = true`、`betrayedThisRound = true`。
- 撕约方**永久失去**结盟资格；当回合盟约事件按新三类走向结算，不再有独立的撕约加成。
- 同盟断链也会被 `incite`（策反）类指定牌强制解除，但不会让任何人获得 `betrayed` 标记。

**同盟互援**：结算第 10 步，仍处于同盟、且未出局、未流亡的双方各 +1 士气。这是同盟的稳定收益，也是撕约的真实代价。

**同盟破裂的判定**：只承认双重互指（A.allyId = B 且 B.allyId = A）。当前实现中，崩溃转流亡会立即**双向**清空 `allyId`；而直接出局（二次崩溃）不会清空 `allyId`，此时幸存者仍指向已出局者——同盟互援与同盟交换资格的判定都会因 `defeated` 被跳过/排除，因此不会产生额外收益。

### 3.10 结算顺序

每回合结算固定按以下步骤执行（`src/utils/game/resolve.ts`），顺序本身就是规则：**先抢点扣钱，再付代价挨打，先扣费后算士气，最后才判濒危**。

| 步骤 | 内容 | 关键细节 |
|---|---|---|
| -1 竞标结算 | 在 `resolveRound` **之前**先 `resolveBids` | 竞标扣补给；放前面保证「透支出价造成的崩溃」轮得到第 11 步判定，也保证日志按时间序（抢点 → 打牌 → 盟约） |
| 0 预掷 | 所有带 `roll` 的已打出牌统一判定成功／失败 | 失败牌不拥有 `immunity`/`truce`/`cancelCounter`/`redirect` 能力 |
| 1 阵营牌 | 已于本回合 `beginRound` 生效 | 优先级最高，早于回合修正与盟约事件 |
| 2 回合修正 | 本回合剧情加减值（3 候选随机 1） | 在 `beginRound` 应用，本轮战报中显示 |
| 3 调停 | 打出的 `truce` 牌（且 `roll` 成功）使打出者与其盟友免受指定牌 | 只保护自己与盟友，其他玩家照常被针对 |
| 4 行动牌代价 | 扣除 `cost`，不分成功失败、不受针对影响 | 代价付完后才处理指定牌，故后续士气奖励按扣费后数值计算 |
| 5 指定牌目标／防御 | 校验目标合法；流亡者的指定牌直接不结算（也不反噬）；受调停保护 → 记 `mediated`；目标有防御牌且成功 → 记 `blocked` | 防御成功时，攻击者按 `backlash` 反噬 |
| 6 击穿／落空 | `counterTag` 与目标本回合打出的 KEY 牌比对 | 命中：KEY 牌归零、写 `nullifiedTags`、攻击者士气 +2（宿敌）／+1；未命中：攻击者补给 +1 且转为「落空」 |
| 7 命中／反噬 | `blocked`/`mediated`/`whiffed` 走反噬；正常则结算 `op`＋牌面 `effects`＋`progress` | `sabotage` 额外使目标本回合指定牌失效；`cut` 会打上切断标记，在本阶段抹掉目标补给的正向收益 |
| 8 行动牌效果 | 结算打出牌（含中立援助）的 `effects` 与 `special` | `requiresAlly` 未满足则效果落空（代价已扣）；`roll` 失败取 `lose` |
| 9 盟约事件 | 本回合判定的盟约事件生效（未触发则跳过） | `allianceEffects` 与 `soloEffects` 同时结算 |
| 10 同盟互援 | 同盟双方各 +1 士气 | 排除出局与流亡者 |
| 11 上限／流亡 | 三项数值封顶 50（流亡者 12）→ 溢出直接截断 → 判崩溃 | 崩溃＝流亡或出局，`everFallen` 置真 |

结算结束后（`round >= 6`）按 [3.12](#312-胜利条件与判定) 判定胜负，并生成阵营牌候选；随后进入结算页。

### 3.11 数值上限、崩溃、流亡与出局

| 概念 | 规则 |
|---|---|
| 上限 `STAT_CAP` | 50。超出部分直接截断 |
| 流亡上限 `EXILE_CAP` | 12。溢出数值**直接丢弃** |
| 崩溃 | 回合结算末尾任一数值 ≤0 |
| 首次崩溃 | 转入**流亡**：三项重置 5／5／5，`exiled = true`、`exileUsed = true`、`everFallen = true`，并**双向解除同盟**；写战报 |
| 二次崩溃 | 流亡者再次崩溃 → `defeated`（出局），不再参与操作与判定 |
| 流亡减益 | ① 上限压到 12；② 带 `tag` 的 KEY 牌**正收益减半**（`floor(v/2)`，最少 1），负值不变；③ 不能主动针对他人（指定牌不结算、不反噬）；④ 不能参与同盟交换候选；⑤ 不参与同盟互援 |
| 流亡保留 | 仍可手牌、仍可再次结盟、仍可被判胜（胜利条件只排除出局者） |
| 出局 | 不再获得手牌、不参与盟约与结算、不参与胜负判定；`allyId` 不清空，但对手因此失去互援与阵营牌资格 |

### 3.12 胜利条件与判定

判定时机：`round >= 6` 的回合结束时（即 R6、R7 各判一次），先判胜者，再决定是否继续。

**R6 提前判胜门槛整体 +2（A1）**：R7 按下方基础门槛判胜；R6 判胜要求同样的目标、但数值门槛统一 +2——「提前结束」应是少数碾压局，否则第 7 回合的专属内容（SARK D7／RI D7／E7 剧情）几乎上不了场。具体到每个阵营，R6 门槛 = 基础门槛的数值部分 +2。

判定顺序与基础门槛（R7）：

1. **萨卡兹军事委员会**：`warProgress >= 3 && morale >= 10`（R6 为 ≥12）。
2. **典范军**：`nullifiedTags` 不含 `国剑`，且人力／补给／士气均 ≥12（R6 为 ≥14），且至少一名其他玩家 `everFallen`。
3. **塔拉／深池**：`nullifiedTags` 不含 `塔拉独立`，且典范军本回合未获胜时士气 ≥13（R6 为 ≥15）；若本局没有在场典范军（未抽取或已出局），改为士气 ≥15 且为全场最高（R6 为 ≥17）（A-05）。
4. **罗德岛**：若萨卡兹的 `nullifiedTags` 含 `阿喃那` → 直接判罗德岛胜（守门人机制，不看自身数值）；否则在**无人达成目标**时，士气最高且 ≥13（R6 为 ≥15）才算胜。
5. **整合运动**：`nullifiedTags` 不含 `新纲领`，人力／补给／士气中**至少两项** ≥10（R6 为 ≥12），且至少一名其他玩家 `everFallen`。
6. **市民自救军**：自身 `everFallen === false`，士气 ≥13（R6 为 ≥15），且至少两名其他玩家 `everFallen === false`。

**同回合多人达成的次级比较（B2）**：不再只按固定顺序取首位，而是先比**士气**（高者胜），士气相同再比**三线之和**（高者胜），仍并列才退回 `SARK > VIC > TARA > RI > REU > SSC` 兜底。出局玩家不参与判定；流亡玩家仍可获胜。

**罗德岛不进并列排序**：RI 是守门人，不参与上述次级比较；只有「成功反制【阿喃那】」或「无人达成目标且士气最高」两条路径（见上文第 4 条）。

若 R7 结束仍无人达成 → 终局页显示「七回合结束，没有任何阵营达成自己的目标」。

### 3.13 战争进度

- **战争进度** `warProgress`：萨卡兹的胜利线，初始 0；来源为 `progress` 字段的指定牌（阿喃那 +2、十王庭／飞空艇／生命脊椎 +1）与同盟交换 F-ST1「军械换进击」（+1）。
- 早期版本还有一个「战绩分 `score`」（围困 +3、数值溢出 +1/点），它既不参与判定也不在游戏中显示，是一套玩家看不见的隐藏记账，已于 v0.2.1 整体移除。

## 五、数据模型

全部类型定义在 `src/types/index.ts`，运行时状态由 Zustand 单一 store 持有，持久化为 `localStorage` 中的一段 JSON。

**联机协议层（`src/shared/protocol.ts`）**

联机版不再用「本地 GameState 存档」，而是**服务端持有权威 `EngineState`**，按视角脱敏成快照下发：

| 类型 | 说明 |
|---|---|
| `RoomPhase` | `lobby` / `briefing` / `picking` / `council` / `resolved` / `result` |
| `RoomView` | 房间公开状态：`roomId`、`phase`、`capacity`、`hostPlayerId`、`seats`、`allReady`、`onlineCount` |
| `SeatView` | 座位对外状态：`name`、`ready`、`connected`、`isHost`、`briefingAck`、`submittedPick`、`councilReady`、`readyNext` |
| `PublicPlayer` | `Omit<PlayerState, 'heldDesignated'>`——除了「保留的指定牌」，其余字段全桌可见 |
| `SelfView` | 自己私有信息：`hand`、`victory`、`submitted`（自己的完整 PlayerState 加手牌与胜利条件） |
| `CouncilView` | 只把「与我相关」的结盟请求发给我（incoming／outgoing），避免全桌围观 |
| `FactionView` | 我这对同盟的交换候选、能否拍板、已谈成的牌、还剩几对没决定 |
| `MatchView` | 对局视图：公开玩家 + `self` + 盟约/剧情事件 + 中立资源点 + 出价（自己的）+ 已出价人数 + 日志 + 胜负 + council/faction 子视图 + 倒计时 |
| `Snapshot` | 完整快照：`seq`（单调递增）+ `serverNow` + `room` + `match` + `you`（重连凭证） |

**客户端消息（`ClientMessage`）**：`createRoom` / `joinRoom` / `setReady` / `leaveRoom` / `briefingAck` / `submitPick`（含出价 `bid`）/ `councilAllyRequest` / `councilAllyRespond` / `councilBreakAlly` / `councilReady` / `factionPick` / `readyNext` / `ping`。

**服务端消息（`ServerMessage`）**：`snapshot`（全量快照）/ `error` / `pong`。

### 5.3 客户端持久化（不再是「存档」）

联机版**没有本地对局存档**——对局进度全在服务端内存里，房间在全员离线超过保留期（默认 24 小时）后回收。客户端只存「重连身份」：

| 项 | 值 |
|---|---|
| 存储键 | `londinium-protocol-net-token` / `-room` / `-name` |
| 内容 | 上次的 `roomId`、`playerId`、`token`、`name` |
| 用途 | 刷新或断线后凭 token 自动回到原座位（`resumeSession`） |
| 本地调试模式 | 仅开发用，`?local=1` 或首页调试入口进入，复用同一 `engine.ts`，不落盘 |

### 5.4 状态机动作（联机版）

引擎侧动作（`src/game/engine.ts`）与服务端消息一一对应：

| 动作（引擎） | 触发消息 | 行为 |
|---|---|---|
| `createEngine` / `joinAsPlayer` | `createRoom` / `joinRoom` | 建房并成为房主 / 凭房间码入座；`joinRoom` 带 token 时按重连处理 |
| `setReady` | `setReady` | 大厅准备状态；四人全准备 → `startMatch` 自动开局 |
| `briefingAck` | `briefingAck` | 确认自己的目标；全确认 → `startRound` |
| `submitPick` | `submitPick` | 记录选牌 + 中立援助处置 + 指定牌 + 出价；全提交（或超时）→ `council` |
| `councilAllyRequest` / `councilAllyRespond` | 同名消息 | 发起 / 回应结盟 |
| `councilBreakAlly` | `councilBreakAlly` | 撕约：双向解除、`betrayed=true` |
| `councilReady` | `councilReady` | 盟约窗口就绪；全就绪（或超时）→ `doResolve` |
| `factionPick` | `factionPick` | 结算页为同盟对拍板交换牌；`cardId=null` 表示这回合不谈 |
| `readyNext` | `readyNext` | 结算页就绪；全就绪（或超时）→ 下一回合或终局 |
| `autoActFor` | 服务端定时器 | 超时托管兜底推进（保守原则） |

| `/round` | `RoundPage` | 简报确认后 | 按 `phase` 切换 `PickingPanel`（暗选 + 竞标）/ `CouncilPanel`（盟约窗口） |
| `/resolve` | `ResolvePage` | 结算后 | 回合标题与剧情、盟约事件（或未触发）、胜者横幅、四宫格状态、战报、阵营牌候选、竞标结果复盘 |
| `/board` | `BoardPage` | 任意时刻（对局中） | 完整日志、玩家状态概览 |
| `/result` | `ResultPage` | 对局结束 | 胜者宣告／无人达成提示、终局日志摘要、再来一局 |
| `/rules` | `RulesPage` | 任意时刻 | 规则速查（六阵营胜利条件、术语） |
| `/guide` | `GuidePage` | 任意时刻（新手引导） | 七步引导：怎么赢 → 一回合做什么 → 术语就地解释 |

### 6.2 关键屏幕说明

| 屏幕 | 元素 | 交互 |
|---|---|---|
| 首页 `HomePage` | 昵称输入、创建房间、加入房间（房间码）、引导入口 | 建房得 4 位房间码；进房输码 + 昵称 |
| 大厅 `LobbyPage` | 房间码（大字号可复制）、4 座位、准备按钮、房主皇冠、在线/断线状态 | 各自点准备，随时取消/离开；四人全准备自动开局 |
| 暗选面板 `PickingPanel` | 手牌区（3 行动牌 + 1 中立援助 + 1 指定牌）、中立竞标面板、倒计时、提交状态条 | 选满 2 张行动牌；中立援助「接受／拒绝」；指定牌「打出／保留／弃置」+ 选目标；可选对资源点出价 |
| 中立竞标 `NeutralBidPanel` | 2 个资源点（名称/奖励/最低出价/已出价人数）、我的出价 | 输入出价金额或放弃；只显示「已有 N 人出价」不显示别人金额 |
| 盟约窗口 `CouncilPanel` | 当前同盟对、可结盟候选、撕约按钮、请求/回应 | 结盟仅列满足 `canAlly` 且无盟友、未撕约的候选；同盟对数上限 2；就绪按钮 |
| 结算页 `ResolvePage` | 回合标题、盟约事件（或未触发）、胜者横幅、四宫格、日志、阵营牌卡区、竞标结果 | 同盟玩家 2 选 1 或放弃；底部「进入下一回合／结束对局」 |
| 全局外壳 `Shell` | 顶部标题、对局总览／规则／引导、回合时间轴、连接状态 | 回合页与结算页不提供返回，防止跳步 |

### 6.3 主流程

1. `/` 一人填昵称 → 创建房间 → 得 4 位房间码 → 进入 `/lobby`；另外三人填昵称 + 房间码 → 加入房间 → 进入 `/lobby`。
2. 四人在大厅各自点准备 → 四人全准备 → 服务端自动开局 → `/briefing`。
3. 各自确认目标 → 全员确认 → `startRound` → `/round`（`picking` 并行暗选 + 竞标）。
4. 四人都提交（或超时托管）→ `council` 盟约窗口（公开结盟／撕约）。
5. 盟约窗口全员就绪 → 服务端结算 → `/resolve`（看战报、选阵营牌、看竞标结果）。
6. 结算页全员就绪 → 下一回合（回到步骤 3）或终局 `/result`。
7. 任意时刻可进 `/board` 看完整战报、进 `/rules` 查规则、进 `/guide` 看引导；刷新或断线由 token 自动重连回原座位。

## 八、验收标准

> 覆盖所有 P0 功能，格式为 Given / When / Then。验收方式：联机实操（起服务端后四人各开一设备进房，或同机四标签页）；自动化验收脚本见 [9.3](#93-启动与构建)。
> F-02／F-16／F-17 为 P1，未单列 Given／When／Then，验收方式见 [6.1 路由表](#61-路由表) 与对应章节。

#### F-01 房间与随机阵营

- **Given** 首页、四人各自有设备
- **When** 一人点「创建房间」、其余三人凭房间码点「加入房间」；四人在大厅点准备
- **Then** 四人全准备后自动进入 `/briefing`，出现 4 张阵营卡；4 个阵营互不相同；至少存在一对 `HOSTILE_PAIRS` 中的敌对阵营。

#### F-03 数值系统

- **Given** 进行到某回合结算
- **When** 某玩家三项数值超过 50
- **Then** 数值被压到 50，超出部分直接截断（不累计、不显示战绩分）。
- **Given** 任一数值被扣到 ≤0
- **When** 本回合结算完成
- **Then** 触发 F-06 的崩溃流程（若有流亡机会）。

#### F-04 回合流程与并行暗选

- **Given** 已进入 `/round`（`picking` 阶段）
- **When** 每位玩家查看自己的手牌
- **Then** 出现 5 张手牌：3 张阵营行动牌 + 1 张中立援助 + 1 张指定牌；四人**同时**可提交，互不影响。
- **When** 4 名玩家全部提交（或超时）
- **Then** 进入 `council` 盟约窗口，且任何玩家都看不到别人已选的卡牌内容。

#### F-05 卡牌系统

- **Given** 选牌阶段
- **When** 查看手牌
- **Then** 显示 3 张阵营行动牌（战略轴互不重复）+ 1 张中立援助 + 1 张指定牌，共 5 张。
- **When** 未选满 2 张阵营行动牌或未做指定牌决策
- **Then** 「确认并提交」保持禁用。
- **When** 已选 2 张行动牌后再点第 3 张
- **Then** 第 3 张无法被选中（行动牌固定 3 选 2）。
- **Given** 手牌中的 1 张中立援助
- **When** 查看牌面与选牌界面
- **Then** 中立援助单独展示、不占 3 选 2 名额，默认随回合打出，可主动弃置；牌面显示 0.45–0.70 的成功率与失败负面。
- **When** 中立援助成功
- **Then** 获得原效果；失败只受轻度负面（-1 补给或 -1 士气），弃置则不结算。
- **Given** 本回合发放的指定牌
- **When** 选择打出
- **Then** 必须选择一位目标玩家，可选任意玩家（包括盟友）；未选合法目标时不可提交。
- **When** 选择「保留到下一回合」
- **Then** 下一回合该玩家在指定牌区看到「上回合保留的指定牌」，且本回合未结算该牌效果（最多保留 1 张）。
- **Given** 回合结算完成、玩家当前处于同盟
- **When** 进入 `/resolve`
- **Then** 显示 2 张阵营牌候选，可选中 1 张或放弃；未结盟玩家不显示该区域、不抽取。
- **When** 选择 1 张阵营牌
- **Then** 效果在下一回合开始前生效，且优先于回合修正与盟约事件。
- **Given** 第 7 回合已结束
- **When** 进入结算
- **Then** 不再提供阵营牌候选。
- **When** 阵营行动牌堆耗尽
- **Then** 弃牌堆自动洗回，抽牌不中断。

#### F-06 流亡机制

- **Given** 某玩家首次崩溃（任一数值 ≤0）
- **When** 结算该回合
- **Then** 三项重置为 5/5/5，`exiled=true`，同盟自动解除，战报出现「转入流亡」。
- **When** 流亡玩家再次崩溃
- **Then** `defeated=true`，出局且不能获胜。

#### F-07 胜负判定

- **Given** 第 1–5 回合结束
- **When** 某阵营已满足目标
- **Then** 不宣告胜利，继续下一回合。
- **Given** 第 6 或 7 回合结束
- **When** 某阵营满足自身胜利条件
- **Then** 结算页出现胜利横幅与理由；若多人同时达成，按「士气高者 → 三线和高者 → SARK > VIC > TARA > RI > REU > SSC」次级比较取首位。

#### F-08 针对与 KEY 牌

- **Given** 萨卡兹打出带【生命脊椎】的指定牌，罗德岛同回合打出针对【生命脊椎】的指定牌
- **When** 结算
- **Then** 萨卡兹该牌事件效果归零，萨卡兹 `nullifiedTags` 增加「生命脊椎」，罗德岛士气 +1（宿敌再 +1）。
- **Given** 被针对方同回合打出含 `immunity` / `cancelCounter` / `redirect` 的牌
- **When** 结算
- **Then** 针对落空，目标牌正常结算。
- **Given** 有玩家打出 `truce` 牌
- **When** 结算
- **Then** 仅针对该打出者与其盟友的针对牌失效，其他玩家的针对照常结算。
- **When** 针对牌目标标签无人打出
- **Then** 攻击者 +1 补给，战报标注「落空」。

#### F-09 同盟与背叛

- **Given** 两位玩家的阵营在 `ALLIANCE_PAIRS` 内且均无同盟
- **When** 在盟约窗口选择双方并点击「缔结盟约」
- **Then** 双方 `allyId` 互相指向，界面显示同盟对；下一回合结算双方 +1 士气。
- **When** 选择敌对阵营组合（如在 `HOSTILE_PAIRS` 内）
- **Then** 按钮禁用，无法结盟。
- **Given** 已有 2 对同盟
- **When** 尝试缔结第 3 对
- **Then** 操作被拒绝。
- **When** 点击「撕毁盟约」
- **Then** 同盟立即解除，发起者 `betrayed=true`，之后无法再结盟。
- **Given** 两位玩家处于同盟
- **When** 回合结算完成
- **Then** 这对同盟共享 2 张阵营牌候选，可谈成 1 张或放弃；未结盟玩家无此环节。

#### F-10 剧情事件

- **Given** 进入第 N 回合
- **When** 服务端 `beginRound` 抽剧情
- **Then** 从该回合 3 候选里随机抽 1 条，各玩家数值按该事件 `deltas` 变化，战报出现该回合剧情与增减益记录。

#### F-11 中立资源竞标

- **Given** 进入 `picking` 阶段
- **When** 查看竞标面板
- **Then** 显示 2 个资源点（名称／奖励／最低出价／已出价人数）；我可对某个点出价或放弃。
- **When** 我对某点出最高价
- **Then** 结算后我独得该点奖励，其余人的出价被扣掉且不退。
- **When** 两人并列最高
- **Then** 该点流拍，谁都不拿、出价照扣。
- **When** 出价低于 `minBid`
- **Then** 视为未出价，不扣补给、不参与该点争夺。
- **When** 暗选阶段查看别人出价
- **Then** 看不到具体金额，只能看到「已有 N 人出价」；结算后才公开全部出价。

#### F-12 盟约事件

- **Given** 场上没有任何盟约
- **When** 结算
- **Then** 本回合不触发盟约事件，结算页显示「本回合盟约事件未触发」。
- **Given** 场上至少一对盟约
- **When** 结算判定（50% 概率）
- **Then** 触发时从三类走向（同盟有利／孤立有利／同盟内部）随机选一，并按对应 `allianceEffects` / `soloEffects` 结算。

#### F-13 联机与重连

- **Given** 对局进行中
- **When** 某玩家刷新或断线后重新打开
- **Then** 凭本地 token 自动回到原座位，回合、数值、日志与断线前一致。
- **When** 查看他人信息
- **Then** 看不到别人的手牌、保留牌、胜利条件、出价金额与同盟交换候选。

**座位与凭证的保留期（v0.4.5）**

| 项 | 值 | 说明 |
|---|---|---|
| 断线保留座位 | 所有阶段（含大厅） | 只有显式「离开房间」才释放座位；刷新、切屏、锁屏都算断线，座位原样保留 |
| 凭证有效期 | **24 小时**（重连时续期，在线时持续续期） | 过期座位在大厅会被释放，避免过期占位把房间锁死 |
| 全员离线保留期 | **24 小时** | 之前是 3 分钟：四个人一起切屏 3 分钟房间就蒸发 |
| 全员离线期间的倒计时 | **冻结** | 无人在线时不执行托管；有人回来按剩余时间继续，回合不会被代打 |
| 空闲房间上限 | 500 个（可配 `MAX_IDLE_ROOMS`） | 保留期变长后的内存保护，超限按最久未活动回收 |

相关环境变量：`TOKEN_TTL_MS`、`EMPTY_GRACE_MS`、`ROOM_TTL`、`SWEEP_MS`、`MAX_IDLE_ROOMS`。

#### F-14 超时托管

- **Given** 进入某阶段
- **When** 有玩家超时未动作（暗选 30s／盟约 45s／结算 60s）
- **Then** 服务端 `autoActFor` 自动托管该玩家（保守原则：不花补给出价、不打指定牌），阶段照常推进、不卡死。

#### F-15 结算与最终报告

- **Given** 一次回合结算完成
- **When** 打开 `/resolve`
- **Then** 显示该回合剧情、盟约事件（或未触发）、四宫格状态、本回合战报、竞标结果复盘；按钮为「进入下一回合」或「查看最终结算」。
- **Given** 已产生胜者或完成第 7 回合
- **When** 进入 `/result`
- **Then** 显示胜者阵营与理由（无胜者时显示「无人获胜」），并给出终局排名。

### 9.5 服务端架构（现状说明）

- `server/index.ts` 是**唯一权威后端**：持有 `rooms: Map<roomId, Room>`，每个房间含 `EngineState`、座位、定时器。
- 每个 WebSocket 连接对应一个座位；消息经 `handleMessage` 路由到引擎动作，动作后 `broadcast(room)` 给房间内所有人推全量快照。
- **脱敏**由引擎的 `viewFor(state, playerId)` 完成，服务端只广播结果，不持有任何客户端逻辑。
- **超时托管**：`bindDeadline` 按 `state.deadline` 设定时器，到点 `onPhaseTimeout` 逐人 `autoActFor` 兜底。
- **房间回收**：房间空了（所有人离开/断线）→ 回收；房间 TTL（默认 6 小时）后过期。
- 已接入真实后端；`VITE_USE_MOCK` / `VITE_API_BASE_URL` 仅作为历史遗留的环境变量，不再使用。

7. 房间与对局状态**只在服务端内存**里：座位与凭证能撑 24 小时，但服务端进程一重启就全丢。要扛重启需接落盘持久化。
