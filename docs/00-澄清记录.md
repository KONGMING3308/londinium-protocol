## 二、已确定的边界

1. 技术栈按 AGENT.md：React 18 + TypeScript(strict) + Vite 5 + React Router v6 + Tailwind + lucide-react。
2. 游戏为本地单机热座，4 名玩家轮流在同一设备操作。
3. 每局从 6 个阵营中随机抽取 4 个，四人阵营互不相同，且至少存在一对敌对关系。
4. 数值维度：人力 M、补给 S、士气 R；上限 50，溢出转战绩分。（v0.2.1 起取消战绩分，溢出直接截断）
5. 每回合每人 5 张手牌：3 张阵营行动牌（战略轴互不重复，3 选 2）+ 1 张中立援助（不占 3 选 2 名额，默认随回合打出、可主动弃置，成功率 0.3–0.8，失败仅 -1 补给或 -1 士气）+ 1 张指定牌（按回合发放，可指向任意玩家，可保留 1 张或弃置）。
6. 指定牌可打出或保留一回合，保留上限 1 张；保留则本回合不结算。
7. 胜负在 R6、R7 回合结束时统一判定，先达成者胜；R1–R5 不判胜。
8. 崩溃（任一数值 ≤0）可触发一次流亡：三项重置为 5/5/5，上限压制到 12，KEY 牌效果减半，不能主动针对他人。
9. 同盟上限 2 对，每名玩家同时只能属于 1 个同盟；仅剧情中实际结盟的势力可结盟（SARK–TARA、VIC–RI、VIC–SSC、RI–REU、RI–SSC、REU–SSC），⚔ 敌对势力不可结盟。
10. 阵营牌为独立全局共用牌池，不按同盟分池；仅当前处于同盟的玩家在结算页获得 2 张候选并选 1 张或放弃，效果在下一回合开始前生效（先于回合修正与盟约事件）；第 7 回合结束后不再提供。
11. 撕毁盟约须在针对牌结算前宣告，宣告当回合立即生效。
12. 结算顺序：阵营牌（下回合开始前）→ 回合修正 → 调停保护（只保护打出者与盟友）→ 行动牌代价 → 指定牌目标/防御 → 击穿/落空 → 指定牌命中或反噬 → 行动牌效果（含成功率判定）→ 盟约事件 → 同盟互援 → 上限/流亡。

## 五、v0.4.0 玩法改动（剧情随机化 + 中立资源竞标）

用户反馈两条：

1. **「现在的剧情修正没有实际效果」** —— 核实后确认：**效果其实一直是生效的**，
   实测 R1 应用后 REU 士气 7→6、SSC 士气 8→9，与剧情表完全一致。
   玩家觉得「没效果」的真实原因是**界面不显示**：
   回合页完全没有剧情展示，结算页只显示叙事文字、不显示谁被加了多少。
   数值悄悄变了但没人知道，等于没发生。

   顺带解决了另一个更根本的问题：原来的七回合是**固定剧本**，
   打两局玩家就能背下来（R3 必定萨卡兹士气 +1），剧情退化成纯数值噪声。
   因此按用户选择改为**每回合三选一随机**。

2. **「中立援助缺少 PVP 要素」** —— 原设计中立援助是「人手一张、各抽各的、各自掷骰」，
   四个人之间零交互，本质是并行的单人骰子游戏。
   改为**每回合刷 2 个中立资源点、四人秘密出价竞标**。

   > ⚠ 口径澄清（v0.4.2 复核）：这里的「改为」是**新增**竞标机制，不是删除中立援助。
   > 两者并存——手牌里仍发 1 张中立援助（掷骰收益，不占 3 选 2 名额），
   > 额外再刷 2 个中立资源点供四人秘密出价竞标。一个是「自己抽到的牌」，一个是「全桌抢的点」，互不替代。

### 为什么是「三选一」而不是「固定剧情 + 随机事件」

保留固定剧情再叠加随机事件，会让第 N 回合必然包含某个已知效果，
玩家仍然可以围绕那个已知效果做规划，随机性被稀释。
三选一让整个回合的天时都变得不可预测，才真正需要临场判断。

### 为什么竞标是「输家的钱不退」

这是这一机制唯一有张力的地方。
如果输了退钱，最优解就是「每回合都出满所有点」，变成无风险摸奖；
不退钱才逼玩家真的判断「这个点值不值得赌」。

### 为什么并列最高价要流拍

否则「大家都出 1 点」会变成四人平分的无风险彩票，
抢点的紧张感完全消失。流拍且照扣，让「猜错」真的有代价。

### 为什么托管不替玩家出价

托管的设计原则是「尽量不改变局势」。出价涉及花玩家的资源，
且金额高低完全是个人风险偏好，托管无从判断。
同理托管也不替玩家打指定牌（涉及针对他人）。
掉线的人会白白错过资源争夺，这是刻意接受的代价。

## 六、v0.4.1 修复（阵营名 / 盟约事件可见性 / 战争进度归属）

用户反馈三个问题，逐一核实后结论如下：

### 1. 「叙拉古和雷姆必拓是哪来的」—— 阵营名写错（真 bug）

`src/utils/game/story.ts` 的 `describeStoryEvent` 手写了一份阵营名映射，
与权威的 `FACTION_MAP` 脱节，把三个阵营写成了方舟里的地名/国家：

| 阵营 id | 错误写法 | 正确写法 |
|---|---|---|
| VIC | 维多利亚 | 典范军 |
| REU | 雷姆必拓 | 整合运动 |
| SSC | 叙拉古 | 市民自救军 |

**根因**：阵营名维护了两份，一份对（`FACTION_MAP`）一份错（story.ts 手写）。
**修复**：删掉手写映射，`describeStoryEvent` 直接读 `FACTION_MAP`，从根上杜绝第二份漂移。

### 2. 「盟约事件没有正常触发 / 效果不明」—— 数值一直生效，但日志不写数值

实测 `resolveRound`：P-01「共同防线」结算后，同盟双方士气 +1、无同盟者士气 -1，
数值完全正确。问题出在**只写叙事不写数值**：
日志是「盟约事件【共同防线】：盟约被摆上台面…」，谁 +1 谁 -1 一个字没有。

**修复**：
- 新增 `src/utils/game/pact.ts` 的 `describePactEvent`，把三档效果翻译成
  「同盟双方 士气+1；无同盟者 士气-1；本回合撕约者 补给+1 士气+2」；
- 盟约事件日志、回合页、结算页三处都补上这句数值。

关于「盟约事件应该只有结盟的人才能看到」：这是规则分歧，已与用户确认——
**保持全员可见**（盟约事件本来就是全场事件，无同盟者也会被孤立效果影响），
只修「效果不明」，不改变可见性。

### 3. 「战争进度应该只有萨卡兹有」—— 逻辑本来正确，但两处表现会误导

结算逻辑（`resolve.ts`）本就带 `factionId === 'SARK'` 判断，非萨卡兹不推进。
但有三处「看起来搞错阵营」的误导：

1. **阵营牌日志会谎报**：`applyFactionCards` 里日志无条件写「甲方战争进度 +N」，
   但实际累加带 SARK 判断。若将来出现甲方非萨卡兹的 progress 牌，日志会说谎。
   → 改成「是否真的推进了才写日志」。
2. **指定牌命中不写进度**：萨卡兹指定牌命中推进了战争进度，但命中日志不提一个字，
   玩家看到面板「战争进度 1/3」却不知道为什么涨了。→ 命中日志补写「战争进度 +N」。
3. **情报牌让非萨卡兹上「战争进度最高」榜**：`reveal` 牌按 warProgress 排序全体玩家，
   萨卡兹出局后会出现「某某(0)」的怪日志。→ 只统计萨卡兹，出局则报「无从查起」。
4. **牌面文案用「甲方/乙方」**：`CardTile` 显示「甲方战争进度 +1」，玩家不知道甲方是谁。
   → 改为直接写阵营名（阵营牌用 pair 阵营名，指定牌用 owner 阵营名）。

### 测试

新增 `scripts/test-pact-story.mjs`（16 项）：阵营名唯一权威来源、盟约事件数值描述、
盟约事件日志带数值、战争进度只归萨卡兹、情报牌只侦查萨卡兹。
挂入 `npm test`（`test:pact`），全量回归 260 项全过。

## 七、v0.4.2 盟约事件重做（概率触发 + 三类走向）

用户反馈：盟约事件「只给盟约成员优势，对孤立玩家不公平」，要求改成：

### 新规则

1. **每回合随机判定是否触发**：场上没有任何盟约 → 不触发；有盟约 → 50% 概率触发。
2. **三类走向随机选一**（触发后从三类里等概率抽一类，再从该类随机抽一张）：
   - **ally-boon**（同盟有利、孤立有害）：如「共同防线」同盟士气+1、孤立士气-1；
   - **solo-boon**（孤立有利、同盟有害）：如「孤军奋起」孤立士气+2、同盟士气-1；
   - **internal**（同盟内部互相有利有弊，孤立者不受牵连）：如「分赃不均」同盟补给+2 士气-1。
3. 每类 2 张、共 6 张；单类内部同时含利与弊，避免退化成单方面白送。

### 关键实现点

- **判定时机移到结算前**：结盟/撕约发生在盟约窗口（council）阶段，
  若在暗选前就抽好事件，会用到上一回合的盟约关系。现在 `doResolve` 用
  「竞标后的玩家状态」判定 `hasAnyAlliance`，再 50% 概率 `pickPactEvent`。
- **「互为盟友」只认双重互指**（A→B 且 B→A），单边残留的 allyId 不算。
- 删除历史字段 `betrayBonus`（撕约加成）——新三类里没有它。
- UI：暗选阶段不再预告盟约事件；盟约窗口提示「结算时随机判定」；
  结算页未触发时显示「本回合盟约事件未触发」。

### 测试

`test:pact` 扩到 27 项，覆盖无盟约不触发、50% 概率、三类都能被抽中、
单边 allyId 不算盟约。全量回归 271 项全过。

### 顺手修掉一个 flake

`test:faction` 偶发「结算页生成 0 对候选牌」：根因是 `incite` 牌与
「崩溃→流亡」会在结算中合法拆散刚结成的同盟，结算后不再互为盟友，
候选牌自然为 0——这是规则不是 bug。测试断言过强，改为「同盟仍成立才断言，
被合法拆散则重开一局（上限 10 次）」。

## v0.4.4 补充（审计待核项结案 + 门槛锁定）

### A-08：审计报告「实录脚本 goalText 为空」的结论

审计报告《七、待核与局限》第二条问：「实录脚本输出的胜利条件字段为空，尚未确认是脚本问题还是引擎未下发」。

**结论：是脚本问题，不是引擎缺陷，无需改动。**

- 协议层从来没有 `goalText` 字段。胜利条件走 `MatchView.self.victory`，类型是 `VictoryDef { title, description }`（`src/shared/protocol.ts` 的 `SelfView`）。
- 且它**只发给本人**：`PublicPlayer` 不含任何胜利条件信息，这是有意为之——公开别人的目标等于泄底。
- 客户端（`src/pages/BriefingPage.tsx`）读的正是 `match.self.victory.title / description`。
- 实录脚本是在引擎层直接取 `player.goalText`，字段名本身就不存在，必然 `undefined`。

## v0.4.5 补充（断线恢复加固：座位与 token 保留一天）

### A-10：实测反馈「一切屏就会重置」的四条根因

四人实测时反馈：切屏回来就被重置、token 应该保持一天。逐条查下去不是单一 bug，是四个缺陷叠加：

| # | 根因 | 修复 |
|---|---|---|
| 1 | **大厅阶段断线 = 离开**：在准备界面刷新一下或手机切屏，座位当场被摘，token 连带作废 | 断线一律保留座位（含大厅），只有显式 `leaveRoom` 才释放 |
| 2 | **全员离线仍执行托管**：四个人一起切屏，30 秒一到托管把全场决策代打完，回合白白推进 | 无人在线时冻结倒计时（`pausedRemaining`），有人回来按剩余时长继续 |
| 3 | **全员离线宽限期只有 3 分钟**：四人一起切屏超过 3 分钟，房间被回收、token 全失效 | `EMPTY_GRACE_MS` 与 `ROOM_TTL` 一起提到 **24 小时** |
| 4 | **token 没有有效期概念** | `TOKEN_TTL = 24h`，重连与在线时续期；过期座位在大厅释放，避免过期占位锁死房间 |

### 保留期一览（v0.4.5）

| 项 | 默认值 | 环境变量 |
|---|---|---|
| 重连凭证有效期 | 24 小时 | `TOKEN_TTL_MS` |
| 全员离线保留期 | 24 小时 | `EMPTY_GRACE_MS` |
| 房间总空闲上限 | 24 小时 | `ROOM_TTL` |
| 空闲房间数量上限 | 500 | `MAX_IDLE_ROOMS` |
| 清理扫描间隔 | 5 分钟 | `SWEEP_MS` |
